`@svelte-i18n/core` infers types from your dictionaries. You don't need to write types or run a code generator for JSON files that you import.

![Editor autocompleting translation keys](/autocomplete-screen-1.png)

## What is checked

Given the setup from [Getting started](/docs/getting-started):

```ts
const { t, setLocale } = useI18n();

t('Change language'); // ✅ autocompleted
t('Hello, {name}!', { name: 'Richard' }); // ✅

t('Hello, {name}!'); // ❌ type error: missing { name }
t('Hello, {name}!', { nam: 'Richard' }); // ❌ type error: wrong parameter

setLocale('nl'); // ✅
setLocale('fr'); // ❌ type error: 'fr' is not a supported locale
```

![Editor showing required parameters for a translation key](/autocomplete-screen-2.png)

## How it works

- **Keys** come from the dictionaries you pass to `createI18n`. Only keys that exist in **every** locale are suggested, so a key you forgot to translate doesn't show up.
- **Parameters** are read from the placeholders in the **key**. `'Hello, {name}!'` requires `{ name: string | number }`.
- **Locales** come from the `locales` array.

## Limits

These are the current limits of the type inference:

- **Unknown keys are allowed by default.** `t('helo')` compiles and returns `'helo'` at runtime. Turn on [strict mode](#strict-mode) to make this an error.
- **Identifier keys have no parameter checks.** With `"welcome_banner": "Welcome, {name}"`, TypeScript sees the value as a plain `string`, so it can't know about `{name}`. Use source-text keys, or write your dictionary in TypeScript with `as const`.
- **Keys added with [`extend`](/docs/extend)** are not part of the inferred types.

## Strict mode

Pass `strict: true` to make unknown keys a type error:

```ts title="src/lib/i18n.ts"
return createI18n({
	locales: [...LOCALES],
	locale,
	strict: true,
	dictionaries: {
		en: async () => (await import('./locales/en.json')).default,
		nl: async () => (await import('./locales/nl.json')).default
	}
});
```

```ts
t('Subscribe'); // ✅
t('Subscibe'); // ❌ type error: not a known key
t(someString); // ❌ type error: only known keys are accepted
```

Strict mode only changes types, not runtime behaviour. Keys added with [`extend`](/docs/extend) are not known to TypeScript, so in strict mode they need to be part of your dictionary type too.

## Remote dictionaries

When dictionaries come from an API, or keys are added with `extend`, TypeScript can't see the keys. Generate an `I18nDictionary` type for them with the Vite plugin or the CLI.

### Vite plugin (recommended)

The plugin finds the dictionaries in your `createI18n` and `extend` calls, including `import('….json')` and `fetch('https://…')`, and keeps `src/lib/i18n-types.d.ts` up to date while you work:

```ts title="vite.config.ts"
import { sveltekit } from '@sveltejs/kit/vite';
import { i18n } from '@svelte-i18n/core/vite';
import { defineConfig } from 'vite';

export default defineConfig({
	plugins: [sveltekit(), i18n()]
});
```

| Option | Default | Description |
|---|---|---|
| `output` | `'src/lib/i18n-types.d.ts'` | Where the type is written, relative to the project root. |
| `fetch` | `true` | Fetch the URLs in `fetch('…')` calls to read their keys. Relative URLs are fetched from the dev server, in dev only. |

The plugin is available since v3.1. Commit the generated file, so type checks in CI work without running Vite first.

### CLI

To generate the type once, or from a URL, use the CLI:

```bash
npx @svelte-i18n/cli generate-types --input src/lib/locales/en.json --output src/lib/i18n-types.d.ts
```

`--input` also accepts a URL. The output looks like this:

```ts title="src/lib/i18n-types.d.ts"
// Generated by @svelte-i18n/cli. Do not edit.
export type I18nDictionary = {
	"Change language": string;
	"Hello, {name}!": string;
};
```

The input must be a flat object of strings. Otherwise the CLI lists each problem and exits with code 1, so you can run it in CI.

Use it as the return type of your loaders so key inference keeps working:

```ts title="src/lib/i18n.ts"
import type { I18nDictionary } from './i18n-types';

// ...
dictionaries: {
	en: async (): Promise<I18nDictionary> => (await fetch('/api/translations/en')).json(),
	nl: async (): Promise<I18nDictionary> => (await fetch('/api/translations/nl')).json()
}
```

> [!TIP]
> Typing the loaders is better than passing the type as a generic (`createI18n<I18nDictionary>(...)`). The generic also turns off locale inference, so `setLocale('fr')` would compile again.
